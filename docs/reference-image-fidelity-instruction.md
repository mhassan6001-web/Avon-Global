# AVEN GLOBAL | REFERENCE IMAGE FIDELITY INSTRUCTION

The Director will provide visual reference images for the AVEN GLOBAL application.

These images are the PRIMARY VISUAL DESIGN SPECIFICATION.

Your task is to carefully inspect every supplied reference image and use the actual visual characteristics as the design blueprint for AVEN GLOBAL.

DO NOT treat the images as loose inspiration.

DO NOT replace their design with a generic dashboard template.

DO NOT independently invent a different visual direction.

## 1. INSPECT EVERY REFERENCE

Inspect every available reference image at its highest available resolution.

For each image, identify and document:

- Overall layout and composition.
- Sidebar position, width and appearance.
- Header structure.
- Navigation style.
- Background colours.
- Colour gradients.
- Typography and font hierarchy.
- Card shapes and proportions.
- Border styles.
- Spacing and alignment.
- Icons and symbols.
- Buttons and controls.
- Charts and visualisations.
- Glass effects and transparency.
- Shadows and depth.
- Animations and transitions where demonstrated.
- Overall atmosphere and visual identity.

Identify which image represents which screen or component.

If an image is missing, corrupted or inaccessible, tell the Director. Do not pretend you inspected it.

## 2. VISUAL FIDELITY

Reproduce the reference design as closely as technically possible.

Preserve:
- The overall composition.
- The visual hierarchy.
- The proportions.
- The placement of elements.
- The colour relationships.
- The visual density.
- The spacing.
- The typography style.
- The distinctive design details.

Do not simplify the reference into an ordinary admin dashboard.

Do not add unnecessary components that change the intended appearance.

Where the reference shows a particular element, reproduce that element rather than substituting a generic alternative.

## 3. AVEN GLOBAL BRAND INTEGRATION

Integrate the AVEN GLOBAL identity into the reference design without destroying its visual character.

The official application name must remain AVEN GLOBAL.

Use the established AVEN GLOBAL brand palette:
- Midnight navy.
- Deep blue.
- Champagne gold.
- Warm white.
- Graphite.

Maintain the futuristic cinematic direction.

The visual result should feel like a sophisticated, premium, next-generation corporate operating system.

## 4. JARVIS INTEGRATION

Integrate the confirmed JARVIS design decisions:

VOICE = CINEMATIC
ACTIVATION = WAKE_WORD
SOUND = IMMERSIVE

JARVIS must feel like a natural part of the interface, not a chatbot pasted into a corner.

Design the listening, thinking and speaking states to fit the reference images.

Include sophisticated waveform animation, microphone status and voice response feedback.

Use original or properly licensed sound effects.

## 5. RESPONSIVE IMPLEMENTATION

The desktop interface should retain the reference design's composition as closely as possible.

For phones and tablets:
- Preserve the same brand identity.
- Adapt the layout intelligently.
- Keep important functions accessible.
- Do not simply shrink the desktop interface.
- Maintain legibility and usability.

Responsive adaptation must not be an excuse to abandon the reference design.

## 6. BUILD A REFERENCE DESIGN REGISTER

Create:

docs/architecture/REFERENCE_IMAGE_SPECIFICATION.md

For every supplied image, record:
- Reference filename.
- Screen or component represented.
- Visual elements to reproduce.
- Layout requirements.
- Colour and typography observations.
- Interaction requirements.
- Responsive behaviour.
- Implementation notes.

Also create a component-to-reference mapping so each screen in the application can be traced to its intended visual reference.

## 7. IMPLEMENTATION AND QUALITY CONTROL

Before implementing any screen:

1. Inspect the corresponding reference.
2. Identify its visual structure.
3. Define the required reusable components.
4. Record the implementation plan.
5. Build the screen.
6. Compare the result side by side with the reference.
7. Identify deviations.
8. Correct deviations before declaring the screen complete.

Do not claim pixel-perfect accuracy without actually comparing the implementation against the supplied images.

Use screenshots at matching viewport dimensions when testing visual fidelity.

Do not use placeholder layouts and claim the design is finished.

## 8. MISSING REFERENCES

If the reference images are not available in the repository or current working environment:

STOP the visual implementation.

Tell the Director exactly which images you cannot access and request that they be uploaded or placed in a clearly named project folder such as:

design-references/

Do not invent what the missing images look like.

## 9. CURRENT INSTRUCTION

First complete the reference inspection and documentation.

If Stage 0 has not yet been approved, do not begin application implementation.

Report the images inspected, the design characteristics extracted, the files created and any missing references.

Wait for the Director's approval before proceeding to implementation.
